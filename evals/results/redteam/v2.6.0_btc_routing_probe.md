# BTC profile routing probe, v2.5.0 against v2.6.0

Not a graded eval. Hand-run investigation through `bin/aw`, which writes
no artefact, so this file is the only record. The counts below must not
be quoted alongside golden suite results.

## Why

The v2.6.0 golden crypto run scored 21/23 against a 23/23 baseline. Both
failures were `lookup_asset_profile` not being called. The queries are
`profile_btc_curated` ("What is Bitcoin?") and
`combined_btc_full_picture`, which decomposes into a profile sub-query
whose text is byte-identically "What is Bitcoin?". So it is one input
failing twice, not two cases failing.

Decomposition was identical across all three v2.5.0 runs and the v2.6.0
run: same `is_single_intent`, same sub-queries, same `intent: profile`,
no fallback, no safety net. Everything upstream of tool selection is
exonerated, which puts the cause in the agent loop's tool-selection call.

Three baseline runs is too thin to establish a change. Three successes
are compatible with a true call rate as low as about 37%. Hence the
probe.

## Method

    ./bin/aw "What is Bitcoin?"

Ten repetitions per arm, reading only whether `lookup_asset_profile`
fired. Same code path, same interface, same everything except the prompt.

The v2.5.0 arm required `ACTIVE_PROMPT_VERSION` to be flipped back
temporarily. `bin/aw` builds from the module-level `SYSTEM_PROMPT`
constant and has no override. The flip was never committed and was
restored in the same session, verified by `git diff --numstat` returning
empty on `aw_analysis/prompts/versions.py`.

## Results

> Amended 26 August 2026. The counts and the p-value in this section are
> superseded. See "Amendment: observation set narrowed" at the end of this
> file before quoting anything below.

v2.5.0, tool called 13 of 13:

- 3 of 3 in the committed golden crypto runs (8 June, 9 June, 12 August)
- 10 of 10 in the probe, latencies 362 to 466 ms, no hesitation anywhere

v2.6.0, tool called 2 of 7:

- 0 of 2 in the golden crypto run (both failures above)
- 2 of 5 in the probe

Fisher's exact on 13/13 against 2/7: p ~ 0.0014 one-sided.

## What this licenses

A p-value is licensed here and is not licensed on the defence rate. This
is repeated sampling of one fixed input under two conditions with only
the condition varying. The defence rate is a coverage statistic over a
hand-curated set with no population and no draw.

The two arms are different behaviours, not one behaviour sampled near a
boundary. v2.5.0 is deterministic across thirteen observations; v2.6.0
calls the tool roughly 30% of the time.

## Suspected mechanism

The v2.6.0 `No tool` clause widened from "general concepts" to "general
market, trading and asset concepts". The word "asset" was added to the
branch that decides when *not* to retrieve, in a system whose primary
retrieval target is asset profiles. "What is Bitcoin?" is the most
canonical general asset concept in the corpus.

The clause was widened to close the product hole on `bnd_04`, `bnd_06`
and `bnd_07`. The effect on the subject side of the same branch was not
considered.

## Not established

The scope test section was also added, immediately above `_how_to_think`,
and may contribute. Separating the two needs a pair of candidate prompts
differing only in the `No tool` wording. Block 7 work.

`profile_btc_curated` also failed its P1 `output_contains(from our
research)` assertion, but only in the run where no tool fired, so nothing
is known about attribution when the tool does fire.

## Amendment: observation set narrowed

Added 26 August 2026, after checking in git whether any code path between
the v2.5.0 and v2.6.0 observations could have moved this string. The
finding does not change. The evidence base does.

Two commits land inside the observation window and needed reading rather
than dismissing.

`1453796` (10 June) reconnects the forced-tool path, so before it
`tool_choice` was always `None`. It cannot touch this string: `FORCE_MAP`
in `aw_analysis/agent/orchestration.py` holds two entries, both PRICE, and
`decide_route` leaves profile and news on AUTO. Profile has never been
forced. Confounder closed by reading, at no cost.

`8026830` (9 June, 16:50) is not dismissible. It swaps `render_examples`
for `render_examples_v2_5_0` inside the v2.5.0 build, between golden run 1
(8 June, 21:13) and golden run 2 (9 June, 22:33). Few-shot content moves
tool selection. So the artefact labelled `v2.5.0_20260608T211326` was
produced by a rendered v2.5.0 that is not the v2.5.0 now pinned by sha256
in `tests/test_prompts_system.py`.

The thirteen v2.5.0 observations therefore span four code and prompt
states, not one. Nothing in that list can plausibly suppress a profile
tool call, so the causal claim stands, but the three golden observations
cannot be treated as replicates of the probe arm.

The v2.6.0 side is clean: `git log c478493..b982343 -- aw_analysis/` is
empty, so the golden run and both probe arms ran on a frozen runtime.

Recomputed, one-sided Fisher's exact:

| observation set | table | p |
|---|---|---|
| all, as originally reported | 13/13 against 2/7 | 0.0014 |
| same code state | 10/10 against 2/7 | 0.0034 |
| same code and same harness | 10/10 against 2/5 | 0.0220 |

The third is the only fully controlled comparison, because the golden
observations reach the string through decomposition and the probe reaches
it through `bin/aw`.

**0.0034 is the working figure. 0.0220 is the conservative one. 0.0014 is
retired** and should not be quoted again. It is not wrong so much as
unearned: three of its thirteen numerator observations came from systems
that no longer exist.

The commit message on `8026830` claims version immutability. That is true
of the legacy builds it left alone and false of v2.5.0 itself, which is
why it survived three months. The run artefact records `prompt_version`
and no digest, so nothing could have caught it. Recording a digest of the
prompt actually passed is Block 7 Stage 2.
